# Demo mode: agent guide

Rules for the demo SPA (`app/demo/`, `shared/demo/`, the seed generator) and for keeping it in step with every
feature. Read [`../../AGENTS.md`](../../AGENTS.md) first. How the demo works (`PIWI_DEMO_MODE=true`, the service
worker, sql.js in IndexedDB, `app/demo/api/router.ts`): the _Demo SPA_ section of
[`ARCHITECTURE.md`](../../ARCHITECTURE.md).

## Demo data requirements

**A feature adding a DB column, an API response field or a UI-visible change updates the demo in five places**, then
runs `npm run app:seed:demo`:

1. `scripts/generate-demo-seed.mjs`: seed the columns;
2. `app/demo/api/`: mirror the response fields;
3. `app/demo/simulator.ts`: emit the new streaming fields;
4. `apps/docs/`;
5. the guided tour, when the change touches a screen a tour stop shows (`app/utils/demo-tour/profiles.ts` and every
   `copy.<code>.ts`, see [`app/utils/demo-tour/AGENTS.md`](../utils/demo-tour/AGENTS.md)).

## The seed

- **`public/demo/seed.sql` is never committed**: it is gitignored and regenerated by `npm run app:seed:demo` (CI runs
  it in `docs.yml` before the demo build). Only `seed.version.json` (the SHA-256 of the SQL and a timestamp) is
  tracked: after editing `scripts/generate-demo-seed.mjs` or `shared/demo/failure-stories.mjs`, re-seed and commit the
  generator with the updated `seed.version.json`.
- **Generation stays deterministic** (seeded PRNG): two runs with no source change write byte-identical SQL. The hash
  is the `demoDataVersion` the demo compares to its IndexedDB copy to offer "New demo data available", so it must move
  only on a real change. `tests/unit/demo-seed-consistency.test.ts` regenerates twice to check it.
- **`shared/demo/failure-stories.mjs` is the single source of truth for every seeded failure**: one story per cluster
  carries the failing spec line, a reporter-faithful error string, the app source files it traces to, and a
  suggested-fix patch _derived_ from those lines, so error, snippet, patch and demo SCM source cannot drift.
  `tests/unit/demo-seed-consistency.test.ts` guards the whole chain. A story's screenshot, trace and video:
  [`scripts/AGENTS.md`](../../scripts/AGENTS.md#demo-evidence-media).
- **A locator-centric story carries an authored failure-time DOM snapshot**, which `app/demo/api/dom-snapshot.ts`
  serves ahead of the committed trace ZIPs (their recorded pages are too bare for the locator picker); the ZIP parse
  stays the fallback.
- **The simulator's failing tests reuse a seeded story's exact error text**, imported from
  `shared/demo/failure-stories.mjs` and never hand-copied, so a simulated failure fingerprints identically and joins
  the real cluster instead of spawning a lookalike. The seed-consistency test checks the parity.
- **The docs link concrete demo screens through `shared/demo/demo-examples.mjs`**, and the seed-consistency test
  checks each example's `expect` against the generated seed (the entity its route opens, the state its sentence
  promises). A seed change that breaks one fails naming the example: update the entry (route, `expect`, `shows`) in the
  same change, never the check.
- **The failure pages' lines never contradict each other over the seed**: `tests/unit/failure-lines-coherence.test.ts`
  lists its rules in its header. A seed or policy change that trips one fixes the lines, never the rule.
- **The web-dashboard Test Map (`shared/demo/demo-test-map.mjs`) is what a live recompute writes**:
  `tests/unit/demo-test-map.test.ts` checks the seeded gaps (`demo-test-map-gaps.json`), control reach and feature
  groups, and scores each detector against the model's ground truth (`expectedWebDashboardGaps`,
  `demo-test-map-benchmark.json`). After a change to the model or a detector, run it with
  `PIWI_UPDATE_DEMO_TEST_MAP=1`, format both files, re-seed and run it again; say in the commit why a score moved.

## Demo-only code

- **Demo AI diagnosis is data-grounded, never canned prose**: rebuilt from the seeded database and each cluster's real
  stats, its suggested patches checked with `validatePatch`.
- **Demo-only AI and SCM code stays out of `shared/handlers/`**, so the canned SCM never enters the server bundle. The
  one shared piece is the version-snapshot row shape (`shared/handlers/diagnosis-versions.ts`).
- **`app/demo/loading-template.html` is what crawlers index**: Nuxt shows it (`spaLoadingTemplate`) until the
  in-browser database is ready. Keep the demo's heading and description in it, and its status text inside
  `data-nosnippet`.
