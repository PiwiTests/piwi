Source code: the attached source archive holds the sources of this exact build. With Node.js 24 and npm, from the archive's root:

    npm ci --workspace=apps/extension --include-workspace-root
    npm run extension:build:release --workspace=apps/extension

The output in apps/extension/dist/ is identical to the uploaded add-on (diff -r). README.md at the archive's root has the details. Vite bundles and minifies the code; nothing is obfuscated and no code is loaded remotely.

Network: none by default. Picking, recording and every page tool run locally. The options page can connect the add-on to the user's own self-hosted Piwi instance (a URL and an API key the user enters). Only the options page and the background script then make requests, to that instance only: they read the project list, the URL patterns, a project's function catalog, its locator index and its bug reports, and they send a bug report when the user clicks Send in a preview that shows exactly what is sent (the recorded steps and the evidence the user kept ticked), and a replay's verdict on a report (the verdict, the site it ran on and the browser's name) when the user clicks Send after Share result. The options page can also pair the add-on with the Piwi Dashboard desktop app on the same machine (a loopback address and token the user pastes); the background script then sends a bug report's title and steps to that address when the user clicks Send in the Run with Playwright preview, and reads back the verdict. Nothing read from a page is sent otherwise, and content scripts never make network requests.

Permissions: activeTab, scripting and storage. The optional host permissions (http://*/*, https://*/*) grant nothing at install: the popup requests one origin when the user starts recording on that site, and the options page requests the instance's origin when the user saves a connection. While connected, a content script registered for that origin only sets one attribute on the instance's pages (data-piwi-picker, the add-on's version), so the instance's dashboard stops suggesting the add-on; it reads nothing from the page and sends nothing. The optional cookies permission grants nothing at install either: Save login for tests requests it, with the one site's origin, when the user clicks Save login file, and writes that site's cookies and localStorage into a file the user downloads; nothing is sent anywhere. devtools_page adds a pane and a panel to the developer tools, which read the inspected page and its network log only while they are open, and send nothing.

innerHTML: every assignment the linter reports inserts either static markup or locator text that the syntax highlighter has HTML-escaped (highlightLocator in packages/picker-dom/src/syntax-highlight.ts, and the overlays' own highlighter in packages/picker-dom/src/overlay-element.ts and overlay-confirm.ts).

Testing: no account is needed. Open any web page, click the toolbar button and pick a tool: Pick an element (click an element to see its ranked locators), Lint overlay, Multi-pick, or Record actions (allow the site, click through a few pages, then Stop to review the generated spec). What needs a Piwi instance (Test functions, Tested elements, and function matching while recording) can be skipped.
