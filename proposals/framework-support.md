# Framework support: what React, Vue, Angular and Svelte apps tell a test run

A proposal to make Piwi read the apps a suite tests as the frameworks that build them: their generated ids, their
routing conventions, the errors they report in the browser, and a nightly check of each. It records what the spikes
showed, the design, the stages and the questions left open.

**Status.** Proposed 2026-11-22, nothing built. Spikes ran React 19.3.1, Vue 3.5.46 and Vite 6 in Chromium through
Playwright 1.64.1 ([section 2](#2-what-the-spikes-showed)). The generated-id rules are
[PiwiTests/piwi#1612](https://github.com/PiwiTests/piwi/issues/1612), fixed apart from this plan (stage S0). Two pieces
are left to proposals of their own: naming the component that rendered an element, and a backend integration for
JavaScript servers (Next.js, Express, Fastify, SvelteKit). Not on [`ROADMAP.md`](../ROADMAP.md) yet. The contracts it
would add are entry D71 of [1.0-stabilization.md](1.0-stabilization.md).

**Summary.** Piwi reads the browser and the test, and knows little of the framework in between. Its rules for
generated ids miss what current React and Vue render. Its routing conventions, which map a changed file to the page it
renders for uncovered changes, gap drafts and both editors, know Nuxt alone. A click under Vite's error overlay is
explained as _covered by another element_. A hydration mismatch, a classic cause of a test that fails on CI and passes
locally, is nowhere in its clues, and React 19 reports one as an uncaught page error, which the capture fixtures do not
keep. Nothing in CI runs Piwi against a React, Angular or Svelte app. This plan detects each app's framework from the
repository, adds the routing conventions of Next.js, SvelteKit, React Router, Astro and TanStack Router, adds clues
for development error overlays, hydration mismatches and framework error codes, and runs one small app per framework
through the reporter every night, against what Piwi should conclude about it.

## Terms

- **Framework**: a UI library (React, Vue, Angular, Svelte, Solid) or a meta-framework built on one (Next.js, Nuxt,
  SvelteKit, React Router in framework mode, Astro, TanStack Router).
- **App root**: the folder holding an app's `package.json`, relative to the repository root.
- **Routing convention**: the rule from a source file's path to the page or server route it implements
  (`app/items/[id]/page.tsx` renders `/items/:id`).
- **Development error overlay**: the element a development server lays over the page when a module fails to compile
  or throws: Vite's `<vite-error-overlay>`, Next.js's, webpack-dev-server's.
- **Hydration mismatch**: the browser's first render of a server-rendered page differs from the server's HTML.

## 2. What the spikes showed

- **Generated ids** (#1612): `react-dom/server` 19.3.1 renders `useId` as `_R_0_` and `_R_0H1_`, `vue/server-renderer`
  3.5.46 as `v-0`, `v-1`, `v-2`. For an element with no role or name, `generateAlternatives` ranks
  `locator('[id="_R_0_"]')` and `locator('#v-1')` first, scored 65, as it ranks `#checkout-summary`.
- **Vite's error overlay**: a module that does not compile puts a `<vite-error-overlay>` element over the page, its
  shadow root holding the message (`.message-body`: `…/broken/main.tsx: Unterminated JSX contents. (1:22)`) and the
  place (`.file`: `…/broken/main.tsx:1:22`). A click on a button under it fails with
  `<vite-error-overlay></vite-error-overlay> intercepts pointer events` in Playwright's call log. The failed module's
  request answers 500, and the console says only `Failed to load resource`: a `script` request, which the capture
  fixtures do not keep.
- **React 19.3 hydration**: a text mismatch is an uncaught page error, `Hydration failed because the server rendered
  text didn't match the client. As a result this tree will be regenerated on the client…`, with no console line.
- **Vue 3.5 hydration**: console warnings `[Vue warn]: Hydration text content mismatch on …` and
  `[Vue warn]: Hydration class mismatch on …`, each naming what the server rendered and what the client expected, then
  the console error `Hydration completed but contains mismatches.`

## 3. Design

### 3.1 Detecting the frameworks

- **A pure function in core**, `@piwitests/core/frameworks`: from the repository's `package.json` files and its file
  list, the apps it holds, each `{ root, name, version, router }`. `name` comes from the dependencies (`next`, `nuxt`,
  `@sveltejs/kit`, `astro`, `@react-router/dev`, `@remix-run/dev`, `@tanstack/router-plugin`, `@angular/core`,
  `@analogjs/router`, `vue`, `react`, `svelte`, `solid-js`), a meta-framework winning over the library under it.
  `router` says which convention applies: `app` or `pages` for Next.js (the folder that exists), `flat` for React
  Router when `app/routes.ts` calls `flatRoutes()`, `file` for TanStack Router with its plugin, `config` for a router
  set in code.
- **The reporter** calls it once in `onBegin` on the tracked `package.json` files (the git inventory coverage takes,
  `internal/coverage-upload/git-inventory.ts`, at most 200) and sends `frameworks` in the run's metadata, at most 20
  apps. `version` is the installed one, read from the app's `node_modules`, else the declared range.
- **A `frameworks` reporter option** declares or corrects the list (`[{ root: 'apps/web', name: 'next' }]`) for a
  layout the detection misreads.
- **The editor service** calls the same function on its workspace, so its conventions match the instance's.
- **What uses it**: the run header names the frameworks (_Next.js 16.0 · React 19.3_), the AI diagnosis's context gets
  one line per app (`server/utils/ai-context.ts`), and 3.2 picks the conventions from it. A run of an older reporter
  carries none, and the Nuxt conventions apply as today.

### 3.2 Routing conventions per framework

`file-routes.ts` gains one convention per framework, each applied relative to its app's root (and to `src/` where the
framework allows it). A file belongs to the app whose root holds it; without detected frameworks, Nuxt's rules apply
to every file, as today.

| Framework                        | Pages                                                                                                                                                                                                | Server routes                                                           |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Nuxt (today)                     | `pages/**/*.vue`, `app/pages/` in Nuxt 4; `(group)` drops out; `[id]`; `[...slug]`                                                                                                                   | `server/api/**`, `server/routes/**`, a method suffix (`orders.post.ts`) |
| Next.js, `app` router            | `app/**/page.{js,jsx,ts,tsx,mdx}`; `(group)`, `@slot` and `_private` folders drop out; `[id]`, `[...slug]`, `[[...slug]]`                                                                            | `app/**/route.{js,ts}`, any method                                      |
| Next.js, `pages` router          | `pages/**` but `_app`, `_document`, `_error` and `api/`                                                                                                                                              | `pages/api/**`, any method                                              |
| SvelteKit                        | `src/routes/**/+page.svelte`; `(group)`; `[id]`, `[...rest]`, `[[optional]]`, `[id=matcher]`                                                                                                         | `src/routes/**/+server.{js,ts}`, any method                             |
| React Router 7 and Remix, `flat` | `app/routes/*`: `.` nests, `$id`, a lone `$` is a splat, `_index` is the parent's index, a leading `_` adds no segment, a trailing `_` keeps the segment without the layout, `(segment)` is optional | Later: a route module with no default export (a resource route)         |
| Astro                            | `src/pages/**/*.{astro,md,mdx,html}`; `[id]`, `[...slug]`                                                                                                                                            | `src/pages/**/*.{js,ts}`, any method                                    |
| TanStack Router, `file`          | `src/routes/**`: `.` or folders nest, `$id`, `$` splat, `index`, `_layout` adds no segment, `__root` is no page                                                                                      | None                                                                    |
| Vue Router, Angular, `config`    | No convention: the routes come from a manifest ([open question](#6-open-questions))                                                                                                                  | None                                                                    |

A method the file declares by its exports (`export async function GET`) is not read: the target matches any method,
as a Nitro handler without a suffix does. Each convention has its unit tests in `packages/core/tests/file-routes.test.ts`,
and the names of the functions callers use stay (`filePageTarget`, `fileRouteTarget`), with the apps as a second
argument.

### 3.3 Clues for what a framework reports

- **Uncaught page errors are kept.** The capture fixtures' `pageerror` listener also adds the error to the execution's
  console entries, type `pageerror`, its message cut as console lines are. _Passed with errors_ then counts an uncaught
  exception of a passing test, as it counts a console error.
- **`dev-error-overlay`** (strong, `shared/failure-clues.ts`): the call log says a development overlay intercepts
  pointer events, or the failure-time page read finds one. The capture fixtures' read of the page state at failure
  (`page_state`) also looks for `vite-error-overlay` and reads its message and place from the shadow root, through
  `internalCall`. Title: _Vite's error overlay covered the page_; detail: the first line of the message and the file,
  linked at the run's commit. It ranks above `element-present-but-blocked`, which it explains.
- **`hydration-mismatch`** (medium; strong when the Attempts diff shows it in the failing attempts alone): a console
  entry or page error matching React's `Hydration failed because`, `A tree hydrated but some attributes of the server
  rendered HTML didn't match`, its production errors #418, #423 and #425, Vue's `Hydration … mismatch` warnings or
  `Hydration completed but contains mismatches.`. The detail quotes the first mismatch (Vue names both values). When
  the project's runs differ in time zone or locale, it names Flake Lab's `timezone` and `locale` conditions, which
  reproduce the commonest cause.
- **`framework-error-code`** (medium): a framework's numbered error in the failing attempt's console, linked to its
  page: `Minified React error #N` to `https://react.dev/errors/N`, Angular's `NG0100` to `https://angular.dev/errors/NG0100`.
- The three clues are deterministic and need no AI; each has a demo story in the seed and an entry in the clue
  reference.

### 3.4 A nightly framework matrix

- **One small app per framework** under `examples/frameworks/`: React with Vite and React Router, Next.js (`app`
  router), Vue with Vite and Vue Router, Angular, SvelteKit. Nuxt is the dashboard's own suite. Each is MIT as
  `examples/` is, a project of its own like `sample-app`, never a workspace.
- **The same app in each**: a sign-up form whose fields are labelled through the framework's `useId` or its equivalent,
  a list with a dialog, a page `/items/:id`, a server route where the framework has one, and two faults behind
  environment variables: a value rendered from the clock on the server and in the browser (the frameworks that render
  on the server), and a module that does not compile (a development server run).
- **One suite**, `examples/frameworks/tests/`, and an `expected.json` per app: the pages and routes the Test Map should
  hold, the file each page maps to, the source files code reach should name, the clue each fault should raise, and no
  suggested locator on a generated id.
- **`scripts/framework-matrix.mjs`** packs and installs `@piwitests/server` and `@piwitests/reporter` into each app the
  way `scripts/package-smoke.mjs` does, runs the suite against a fresh dashboard, reads the run back through the API,
  and compares it to `expected.json`.
- **`nightly-frameworks.yml`** runs it each night, one job per framework, results as an artifact kept 14 days, as
  `nightly-showcase.yml` does. It never runs on a pull request: the installs are large and the check is slow.
- Dependabot keeps each app's framework current (`examples/frameworks/*` beside `examples/sample-app/backends/*`), so a
  framework's new id format or overlay reaches the matrix within a week of its release.

## 4. Left out

- **The component behind an element.** Vue and Svelte development builds name the component and its file on the
  element, Angular through its `ng` debug API; React 19 dropped the source location it used to keep. Recording it beside
  each locator would point a failure at `CheckoutSummary.vue:42`. It needs a spike per framework and is a proposal of
  its own.
- **A backend integration for JavaScript servers.** Backend logs, server spans and server code reach come from the
  Nitro and ASP.NET Core packages alone. Next.js's `instrumentation.ts`, or one OpenTelemetry-based Node package, could
  bring them to Next.js, Express, Fastify and SvelteKit. A proposal of its own.
- **Component tests**: [component-tests.md](component-tests.md).

## 6. Open questions

- **Routes of a router set in code** (Vue Router, Angular, React Router in library mode). The page may expose them
  (Vue's app instance on its mount element, Angular's debug API in development), or a `piwi manifest` command could
  write `piwi.manifest.json` from the build. Neither has been tried.
- **Next.js's and webpack-dev-server's overlays**, and whether Angular's development server shows Vite's: their
  elements and where their message sits, to confirm in the matrix before `dev-error-overlay` reads them.
- **Pinned or latest versions in the matrix.** Pinned versions with Dependabot keep a night's failure reproducible;
  `latest` would catch a framework change the day it ships.
- **A hydration mismatch in a passing test**: whether it is a finding of its own, beside _Passed with errors_, since
  the page still worked.
- **Several apps in one repository** that one suite tests: which app a page belongs to, when the conventions of two
  apps map files to the same path.
